# Contract size measurements — undeployed v2.5 candidate

No deployment, transaction, funding, key change, state-layout change or public ABI change.
The release identity and SHA256 are generated by `scripts/gen-identity.mjs`; live
`identity.json` and the deployed v2.4 artifact are unchanged.

## Measurements

Each successful build used the pinned `contracts/keys/build.sh`, rustc 1.86.0,
cargo-near 0.22.0 and Binaryen 123. One build at a time, one Cargo job.
All byte counts below include the final `-Oz --converge` pass, not raw Rust output.

| Step | Wasm bytes | Decision |
|---|---:|---|
| Pinned z baseline (reproduced locally) | 495199 | baseline |
| s instead of z | 518015 | rejected: larger |
| Scalar JSON fields instead of Value trees | 491892 | intermediate |
| Shared slice-based JSON object encoder | 485855 | retained |
| Additional merge-similar-functions pass | 485857 | rejected: larger |
| Remove unstable SDK feature | build refused | rejected: required for near_sdk::sys bounded promise results |
| Remove default SDK allocator; retain unstable | 491949 | rejected: larger |
| LLVM inline and inlinehint thresholds zero | 495912 | rejected: larger |
| Restore retained source/recipe, rebuild | 485855 | identical bytes |

`lto=true` is fat LTO; one codegen unit, panic abort, no debug, checked arithmetic,
no embedded ABI and stripped debug/producers were already present and remain.
No dependency version changed, and no panic text or public JSON serializer changed.
The two production dependencies are both used. The `unstable` SDK feature is needed
for bounded host register access; omitting it does not compile. Switching off SDK
default features increases this artifact, so the release retains its allocator.

## Code-level change

Internal callback arguments and custom event objects no longer construct a dynamic
`serde_json::Value` tree. Each scalar still uses Serde's original JSON serialization
(including AccountId, U64/U128 strings, Base64, nullable strings, booleans and escaping).
One shared slice-based helper sorts the statically named fields, preserving the exact
BTreeMap order and JSON bytes. No contract method, JSON view or Borsh type changed.
The new regression compares legacy JSON bytes for every field shape, including maximal
integers, null/Some, Unicode, quotes, backslashes, control bytes and reusable inputs.
The complete generated ABI body is equal to the baseline (86 functions).
A repeated full pinned build is byte-for-byte identical to the first retained build.
Runtime/unit/worker/web status is recorded by the exact-head GitHub checks, not inferred
from these size measurements. No below-gate sandbox, worker or web suite was started locally.

## Profiler

Twiggy 0.8.0 was installed as a single-job, unoptimized local diagnostic tool.
[Final top 20](size-profile/final-top20.txt) profiles the exact stripped release artifact;
[baseline top 20](size-profile/baseline-top20.txt) profiles the previous release.
Stripped function identifiers are intentionally reported as `code[n]`, not guessed names.
Supplementary [baseline raw symbols](size-profile/baseline-raw-named-top20.txt),
[final raw symbols](size-profile/final-raw-named-top20.txt), and
[generic families](size-profile/final-raw-generics.txt) profile the named Rust output
BEFORE cargo-near/Binaryen optimization. Raw symbol bytes are not release byte counts.

The largest generic family is JSON `deserialize_struct`: 79 specializations, about
148 KB of raw code. Other contributors include the JSON parsing trampolines, base64,
float formatting used in JSON type-error reporting, and the loan/sale state machines.
The default Rust/Serde argument wrappers and exact error behavior remain intact;
JSON/Borsh interface conversion or removing those error paths was not used to claim a win.
