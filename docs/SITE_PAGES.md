## 3. Try it

### Try it in 2 minutes (no wallet)

Each step has a command or a link. The words after **See** are what you should get.

1. **Check the claims, offline.** Do (from this checkout): `node judge/verify-claims.mjs --offline`. See: `689 claims: 365 PASS, 0 FAIL, 0 ERROR, 324 SKIP` (current repair). The passing checks are file, path and symbol checks in this checkout. The skipped claims read mainnet, the live site, attestations or CI. The strict public-read run recorded on main before this candidate passed **610/610 claims, 0 FAIL, 0 ERROR, 0 SKIP**; it uses existing attestations and never starts paid compute. That online result does not validate this candidate. The offline run reads only files in the repo. Without `--offline` the script also reads mainnet, the live site, the attestation API and the CI runs. Requires Node 18+.
2. **Open the verifier on the live build.** Do: open [www.getkeyhole.xyz/verify](https://www.getkeyhole.xyz/verify). See: the **Live evidence pack** table (contract code hash, operator keys, NFT supply, worker attestation, deploy/publish/handover txs) with PASS/FAIL, then the 37 TEE checks for current call `962d4374…`. No wallet.
3. **Try to steal a key.** Do: open [www.getkeyhole.xyz/attack](https://www.getkeyhole.xyz/attack). See: each card re-fetches a real attested refusal (`bad_params`, `over_cap_per_tx`, `replay`, `bad_signature`, `not_owner`, `locked`) or the handover transfer tx; badges name the recorded wasm (e.g. previous build `6367401a`) and live-check vs evidence. No wallet and no value moved.
4. **Open the verification path.** Do: open [www.getkeyhole.xyz/judge](https://www.getkeyhole.xyz/judge). See: seven numbered checks. Each has a button that runs in your browser and a box that says what the correct result is.
5. **Open a key's history.** Do: open [www.getkeyhole.xyz/key?id=k5f4750858f328940](https://www.getkeyhole.xyz/key?id=k5f4750858f328940). See: the holders with from and to dates, deposits, withdrawals and its recorded transfer. The page shows "19 events chain, head matches, head signed, signer is the TEE minter. Confirmed", re-checked in your browser.
6. **Check that the contract on chain is the repo's wasm.** Do: `bash ./judge/1-contract.sh` (needs `bash`, `curl`, `jq`, `sha256sum` and `python3`). See: `on-chain code_hash 3cZsaySY…KGZH`, then `OK   contract code matches the committed wasm`, then `OK   minter is an implicit account`.
7. **Verify one call from the terminal.** Do: `cd cli && npm ci && npx tsx src/cli.ts verify 962d4374-b9ec-411a-9efa-973b36260431`. See: `"ok": true` and three `OK` lines: TDX quote present; registered wasm_hash equals executed_wasm_sha256; FastFS bytes equal the attested hash. No key is needed. Previously checked with `./verify.sh` (the same checks, plus FastFS) on `dc3668db`.
8. **Open an attested refusal.** Do: open [www.getkeyhole.xyz/verify?call=a02613a2-d503-45e2-83b8-ef71927c2533](https://www.getkeyhole.xyz/verify?call=a02613a2-d503-45e2-83b8-ef71927c2533). See: the attestation checks pass. The refusal is `over_cap_per_tx`: a 2 USDC swap against the $1 Bronze cap. The attestation has no output body, so the recorded outcome is in [`docs/evidence/mainnet-e2e/15_overcap_swap_2usdc.json`](../docs/evidence/mainnet-e2e/15_overcap_swap_2usdc.json).
9. **Use the agent path (optional).** Do: run `keyhole-mcp` ([`cli/src/mcp.ts`](../cli/src/mcp.ts)), a stdio MCP server with `verify`, `explain_pnl`, `quote_buy`, `pledge_status` and `copy`. See: `verify` needs no key. `pledge_status` reads the chain and signs nothing ([`cli/test/pledge.test.ts`](../cli/test/pledge.test.ts)). `copy` needs the operator to type a code on the operator's own terminal; the code never appears in a tool result.
10. **Open the Pledge preview.** Do: open `/pledge` on a local build of this checkout, or [www.getkeyhole.xyz/pledge](https://www.getkeyhole.xyz/pledge). See: headline **Borrow NEAR without publishing your full balance**; whole-account collateral warning; locked USDC/NEAR chips (no fake asset picker); tier exit-caps line; How it works column; floating key art unclipped; sidebar **Pledge** lit. Banner **Preview — in review · not live**. CTA disabled: **Pledge launches after audit**. Example terms labelled **Example** (0.50 USDC / 0.01 NEAR); due line marked example until live `get_loan`. Density matches the other dashboard pages (fits 1440×900 and 1280×800 without scrolling). No wallet and no value moved. Live lending stays behind `NEXT_PUBLIC_PLEDGE_LIVE` until the reviewed contract (PR #184 method surface: `open_loan`, `fund_loan`, `repay_loan`, `claim_default`, …) and audit gate clear.
11. **Read a key timeline.** Do: open [www.getkeyhole.xyz/key?id=k5f4750858f328940](https://www.getkeyhole.xyz/key?id=k5f4750858f328940) and read Timeline. See: the signed log rows, then **Now, from the contract** for the current owner and lien ([`web/components/keylog/KeyTimeline.tsx`](../web/components/keylog/KeyTimeline.tsx), [`web/tests/keylog.test.ts`](../web/tests/keylog.test.ts)). No wallet.
12. **Read the lien.** Do: open [www.getkeyhole.xyz/verify](https://www.getkeyhole.xyz/verify) on this build, enter `k5f4750858f328940`, and press **Read lien**. See: the owner from `nft_token`, whether the key is locked, and the lending line from `get_pledge_config`. The same panel is on the key page. Proof: [`web/components/lien/LienPanel.tsx`](../web/components/lien/LienPanel.tsx), [`web/components/lien/useLien.ts`](../web/components/lien/useLien.ts), [`web/tests/lien.test.ts`](../web/tests/lien.test.ts), [`web/tests/lien-read.test.ts`](../web/tests/lien-read.test.ts). No wallet and no transaction.
13. **Check a holder.** Do: open `/holders` on this build ([`web/app/holders/page.tsx`](../web/app/holders/page.tsx); the public URL is [www.getkeyhole.xyz/holders](https://www.getkeyhole.xyz/holders) once this branch is deployed). Connect the wallet that holds a key and press **Check my key with a wallet signature**. See: that account's tier and key ids, or the not-a-holder line. A switch of account clears the previous result ([`web/app/holders/view.tsx`](../web/app/holders/view.tsx), [`web/tests/holder-check.test.ts`](../web/tests/holder-check.test.ts)). Production `GET /api/gate` returns 503 until the server env var `HOLDER_GATE_SECRET` is set ([`web/app/api/gate/route.ts`](../web/app/api/gate/route.ts), [`web/tests/holder-gate.test.ts`](../web/tests/holder-gate.test.ts)). The value is not in this repo. This step does not record a captured grant.
14. **Exit dry run.** Do: on a build with `NEXT_PUBLIC_PLEDGE_LIVE` set to `1`, open the borrower pledge screen, read private inventory, and press **Exit to my wallet**. The public site leaves that flag unset, so [www.getkeyhole.xyz/pledge](https://www.getkeyhole.xyz/pledge) stays on the preview in step 10. See, when the flag is on: a confirm that names `amount_out` and the minimum before any withdrawal signature. Cancelling signs nothing. A redirect wallet (MyNearWallet, Meteor web) returns to the same preview and does not start a second withdrawal. Proof: [`web/lib/withdrawDryRun.ts`](../web/lib/withdrawDryRun.ts), [`web/lib/exitContinuation.ts`](../web/lib/exitContinuation.ts), [`web/app/pledge/LivePledge.tsx`](../web/app/pledge/LivePledge.tsx), [`web/tests/withdraw-dry-run.test.ts`](../web/tests/withdraw-dry-run.test.ts), [`web/tests/exit-continuation.test.ts`](../web/tests/exit-continuation.test.ts). 15. **Read pledge status from the chain.** Do: `cd cli && npx tsx src/cli.ts pledge status k5f4750858f328940`. See: `not locked (owner …)` with the owner from `nft_token`, and the lending line from `get_pledge_config` (lending off while the contract says so). The same read is the MCP tool `pledge_status`. Proof: [`cli/src/pledge.ts`](../cli/src/pledge.ts), [`cli/src/cli.ts`](../cli/src/cli.ts), [`cli/src/mcp.ts`](../cli/src/mcp.ts), [`cli/test/pledge.test.ts`](../cli/test/pledge.test.ts). Views only. Nothing is signed.
16. **Try the key on testnet, no wallet and no sign-up.** Do: open [www.getkeyhole.xyz/try](https://www.getkeyhole.xyz/try) (also linked from the home hero, [/start](https://www.getkeyhole.xyz/start) and [/judge](https://www.getkeyhole.xyz/judge)). See: the banner **Testnet · free · not real money** and a Mainnet toggle. One click creates a guest testnet account; the key stays in the browser. A practice key is minted on the testnet deployment of this repo’s v2.7 keys contract, recorded in [`docs/trial/testnet.json`](../docs/trial/testnet.json) (code hash matches [`contracts/keys/release/v2.7/identity.json`](../contracts/keys/release/v2.7/identity.json)). Transferring it to a second guest moves the owner, and the old holder’s next transfer is refused by the contract. The trade step does not send a trade. It shows the recorded mainnet swap, labelled **recorded on mainnet**, at [/verify?call=09d58c09-c1e9-48b6-bebb-485f5ae79539](https://www.getkeyhole.xyz/verify?call=09d58c09-c1e9-48b6-bebb-485f5ae79539) ([evidence](../docs/evidence/mainnet-e2e/08_swap_0.005_usdc.json)). Guest creation is a sponsored `create_account` on the testnet top-level account ([account creation](https://docs.near.org/tools/near-api), [faucet](https://docs.near.org/getting-started/faucet)). Each guest is funded with 0.05 testnet NEAR, the `GUEST_DEPOSIT_YOCTO` constant in [`web/lib/trialPublic.ts`](../web/lib/trialPublic.ts). The sponsor key is the server env var `KEYHOLE_TESTNET_SPONSOR_SECRET` and is not in the repo.

### Try it with a wallet

**Sign in** with a NEAR wallet (including Meteor and HOT through the wallet selector), MetaMask (signs with EIP-191 `personal_sign`), or Google or email on [/start](https://www.getkeyhole.xyz/start). The Google and email path creates an embedded NEAR account through Privy, so Privy sees that login. A wallet sign-in does not use Privy. No KYC and no region check are asked for.

Each step says whether it **moves real value on mainnet**. Payable mint/list operations require their prepaid payout slots and explicit onboarding; the current read-flow PASS does not certify every payable flow. [Operational boundary](../SECURITY.md#historical-v26-restoration-not-the-live-release).
